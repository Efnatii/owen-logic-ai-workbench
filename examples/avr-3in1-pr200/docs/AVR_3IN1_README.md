# AVR 3-in-1 for PR200

Папка содержит ST-блок для ОВЕН Logic/ПР200 и проверочный симулятор с тестами.

## Файлы

- `FB_AVR_3IN1_PR200.st` - основной функциональный блок с латинскими именами переменных и русскими описаниями в `Description`.
- `FB_AVR_3IN1_PR200_MODULAR.st` - та же логика, разбитая на простые функциональные блоки.
- `MODULAR_CONNECTION_TABLE.md` - таблица соединения малых блоков на FBD.
- `MODULAR_BLOCK_DIAGRAM.md` - визуальная схема соединения малых блоков.
- `MODULAR_FULL_WIRING_DIAGRAM.md` - полная блок-схема со всеми соединениями.
- `FBD_FULL_WIRING.svg` - FBD-рисунок со всеми блоками, пинами и проводами.
- `FBD_FULL_WIRING.png` - PNG-превью FBD-рисунка.
- `MOUNTING_SCHEME.md` - простая монтажная схема: один блок АВР и номера цепей.
- `MOUNTING_SCHEME.svg` - картинка монтажной схемы без детальной прорисовки логики.
- `MOUNTING_SCHEME.png` - PNG-превью монтажной схемы.
- `avr_3in1_sim.py` - Python-модель той же логики для доказательных тестов.
- `test_avr_3in1.py` - 35 сценариев проверки.
- `test_avr_3in1_invariants.py` - 24 инвариантных/статических теста, включая полный перебор входов, состояний и внутренних состояний задержки.
- `TEST_REPORT.txt` - последний отчет успешного прогона тестов.

## Важный принцип

В блоке нет библиотечных таймеров и тайм-аутов. Переключение строго привязано к допконтактам автоматов, а задержка применяется только к принятию нового целевого ввода:

- команда отключения держится до подтверждения `xQF*Off = TRUE`;
- команда включения держится до подтверждения `xQF*On = TRUE`;
- следующий ввод не включается, пока все остальные вводы не подтверждены выключенными;
- промежуточное положение `On = FALSE` и `Off = FALSE` допускается только для автомата, которому сейчас дана команда;
- противоречие `On = TRUE` и `Off = TRUE` всегда считается неопределенным состоянием.

`udiInputDelaySec` задает задержку перед сменой целевого ввода. В ST нет `TON`, `TIME` и второго внешнего импульсного входа: задержка считается внутренним `UDINT`-счетчиком циклов вызова блока. Если блок вызывается один раз в секунду, значение параметра равно секундам. Если `udiInputDelaySec = 0`, логика работает без задержки.

Для ПЭСПЭЗ логика сделана жестко безопасной: при неопределенности или аварии включающие команды блокируются, а при пересечении вводов разрешаются только команды отключения уже включенных вводов.

## Логика входов

Все входы подаются уже в смысловой логике после внешних инверсий:

- `xManualSelector`: `TRUE` = переключатель закрыт, выбран ручной режим.
- `xAutoReturn`: `TRUE` = возвращаться на более приоритетный ввод.
- `udiInputDelaySec`: задержка подтверждения смены целевого ввода, секунд.
- `xU1Ok`, `xU2Ok`, `xU3Ok`: `TRUE` = напряжение ввода в норме.
- `xQF1On`, `xQF2On`, `xQF3On`: `TRUE` = автомат включен.
- `xQF1Off`, `xQF2Off`, `xQF3Off`: `TRUE` = автомат выключен.
- `xQF1Fault`, `xQF2Fault`, `xQF3Fault`: `TRUE` = авария автомата.

Отдельного входа "сигнал ДГУ отправлен" нет.

## Выходы на ПР200

- `xQ1 -> Q1`: включить `40F`.
- `xQ2 -> Q2`: выключить `40F`.
- `xQ3 -> Q3`: включить `50F`.
- `xQ4 -> Q4`: выключить `50F`.
- `xQ5 -> Q5`: включить `60F`.
- `xQ6 -> Q6`: выключить `60F`.

## Диагностика

- `xAlarmFault`: авария `40F/50F/60F`.
- `xAlarmParallel`: включено больше одного ввода.
- `xAlarmUndefined`: неопределенное состояние допконтактов.
- `xQF1Undefined`, `xQF2Undefined`, `xQF3Undefined`: неопределенность по конкретному автомату.
- `udiRawTarget`: целевой ввод по мгновенному состоянию напряжений до задержки.
- `udiTarget`: подтвержденный целевой ввод после задержки.
- `udiPendingTarget`, `udiDelayCounterSec`, `xTargetDelayActive`: диагностика ожидания задержки.
- `xNoSource`: нет доступного ввода.

## Снятие аварийного режима

Авария автомата, пересечение вводов или неопределенность допконтактов переводят АВР в `xManualMode`.

Режим снимается автоматически, когда все аварийные условия ушли:

- `xQF1Fault = FALSE`, `xQF2Fault = FALSE`, `xQF3Fault = FALSE`;
- нет пересечения вводов;
- допконтакты включен/выключен не находятся в неопределенном состоянии.

Переключать авто/ручной для сброса аварийного режима не нужно. `xManualSelector` отвечает только за физический ручной режим от переключателя.

## Запуск тестов

```powershell
cd C:\__SELF_PC__\AVR_3IN1_PR200
python -m unittest discover -v
```

Полный прогон сейчас содержит 59 тестов. В инвариантных тестах перебираются 16 384 комбинации входов на каждое состояние автомата, плюс отдельный полный перебор внутренних состояний задержки.
